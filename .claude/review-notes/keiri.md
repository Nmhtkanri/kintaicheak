# 経理モード（jinjer 給与明細 → freee 仕訳）— 2026-09-10 転記・同日コード検証済

## 入口
- 給与（月次 4CSV）: `/keiri_run` `/keiri_sonota_save` `/keiri_download/<ym>/<path:filename>`
- 賞与（2026-09-10 追加）: `/keiri_bonus_run`（multipart で賞与 CSV をアップロード）。ダウンロードは同じ `/keiri_download`。画面は経理カード内の「給与／賞与」切替タブ（`#keiri-subtabs`、`keiriSubMode`）。
- services: `keiri_engine` `keiri_api` `keiri_diff` `keiri_keihi_tenki` `keiri_bonus`（賞与）

## 入力
- jinjer API の給与明細（キャッシュは社労士モードと共用）。
- **経費チェックモードが出力する `経費統合一覧表.xlsx` は読まない。** ただし `経費利用履歴 RevN.xlsm` の中の「経費統合一覧表」シートは読む（`services/keiri_keihi_tenki.py` で allowance52 の分解に使う「備考(明細)」を取る。列は定数直書き `I_MEMO_LINE = 19`、行の引き当ては「集計ログの行番号＝シートの 1-based 行番号」という前提）。このシートの列追加・並べ替え・行ズレは備考の科目判定を壊す。
- 外部マスタ（`config.py`）：品目マッピングマスタ `KEIRI_MASTER_CSV`、経費転記マッピング `KEIRI_KEIHI_MAPPING_CSV`、経費利用履歴ブックの置き場 `KEIRI_KEIHI_BOOK_DIR`。マスタ 1 行の変更で freee CSV の中身が変わる。
- その他台帳 CSV（手入力分の科目決め）。2026-09-10 から同じ支給月・社員番号に複数行を持てる（画面の ＋／− で行を分け、金額の合計が jinjer の金額と一致するときだけ行ごとに仕訳）。保存は一時ファイル経由。支給月が YYYY-MM でない行（Excel 保存で化ける）は要確認 md に出る。2026-09-11 から列に「部門」「明細社員番号」が増え、画面で社員番号・氏名・部門も直せる（明細社員番号＝jinjer で「その他」が入っている人＝台帳のキーと金額の突合相手、空欄なら社員番号。社員番号＝仕訳を載せる人。氏名・部門が空欄ならその人の名簿・履歴の値。画面で入れた部門が部門マスタ 8 種に無ければ要確認 md の「部門マスタに無い部門値」に出る。画面は氏名・部門が初期値（data-init）のままなら空で送る（台帳に焼き付けず毎回 jinjer から決める。別人にした行ならその人の既定）。計上先が名簿に無い番号なら alert sonota_emp_unknown で md に出し、仕訳の従業員は空になる。md の「台帳から計上」表に 計上先・部門 列がある。宿題: 旧 exe から同じ月を保存すると 部門・明細社員番号 の列が消える＝exe 入替前は付け替え機能を使わない）。追加投入 5 項目（定常外業務対応手当・その他手当・現物支給・支給過不足調整・社保調整）は自動計上。
- **賞与**の入力は API のみ（画面）。CSV アップロード（賞与支給控除項目一覧表、121 列・cp932）はルート `/keiri_bonus_run` の source=csv に裏口として残すが画面には無い（2026-09-11 谷津さん判断）。2026-09-11 に API 入力を追加（`rows_from_api` が API 応答を CSV と同じ列名の行にして `build_bonus` に流す。支援金は 本人＝標準賞与額×率÷2 の五捨六入・事業主＝同額 で計算し、総支給額−差引支給額−API の控除合計 と突き合わせて検算。支払期日は画面指定が優先。キャッシュ raw/bonus_statements_{月}.json）。**API に賞与計算結果がある**（`GET /v1/employees/bonus-statements`、パラメータ executed-on（計算対象月）・employee-ids・page。2026-09-11 に実 API で確認。「API に無い」という 9/10 の記述は誤り）。API の項目: bonus_items（allowance1 賞与…）、bonus_deduction_items（deduction6 雇用／7 健保／8 介護／9 厚年／10 基金／18 年調過不足／19 所得税）、bonus_other_items（other13〜19 が事業主負担＝雇用・労災・健保・介護・厚年・基金・拠出金、other31/32 が健保・厚年の標準賞与額、other30 所得税率、既払系）。**子ども・子育て支援金は本人側・事業主側とも API に出ない**（CSV には両方ある）。給与の API も同じで、支援金の事業主負担だけが無い。API の paid_on は 2026-09-08（処理基準日と同じ）で、CSV の支給日 9/25 と違うので支払期日には使えない可能性がある。規則は `services/keiri_bonus.py` の冒頭に記載（賞与手当＝総支給額、預り金＝本人控除の各列、会社負担＝標準賞与額×総率÷2 の四捨五入、拠出金は本社 1 行）。料率は `Z:\API連携\docs\経理モード_賞与料率.csv`（無ければコード内の 2026 年度既定値）。

## 出力と不可逆な処理

## 業務ルール
- 社保の 1 か月ズレ：会社負担＝当月分／本人控除＝前月分。**健保・厚年ファイルの①主取引（前月分の会社負担）と②預り金は、当月明細の本人控除（deduction29/30/31・child_support）から読む**（2026-09-10。`COMPANY_TO_HONNIN` でマスタ行のキーを読み替え）。前月明細の会社負担は、標準報酬が前月の給与計算の後に登録された月に旧額のままになる（2026-07 は 7/31 に 33 人分が管理者登録）。③退職者分だけは当月明細の会社負担×0.5。免除判定・入社判定は会社負担側（`company_total`）で行う。
- 子ども・子育て支援金は API に会社負担側の項目が無い（jinjer 画面の「事業主保険料 > 子ども・子育て支援金」は salary_other_items に来ない。2026-04〜08 で確認）ので、本人控除 child_support で代用している。
- 要確認 md に「前月明細の会社負担と当月明細の本人控除が違う人」の一覧が出る（後追い登録・2 か月分控除・徴収漏れの検知。金額は変えない）。月変の無い月は「なし」になるはず。
- その他手当は allowance20/21 の 2 つある。調整手当は allowance15→12 へ移設済み（2026-08）。暫定固定項目には 12 と 15 の両方を残している。
- 対象外項目の新規使用検知：画面赤枠・人数金額・要確認 md（先頭見出しと「骨格の未実装（TODO）」節の次）に出す。`KEIRI_NEW_USAGE_BLOCK` で停止切替（既定オフ、テストで assert 済）。要確認 md の新規使用検知を毎月見る。

## 既知の落とし穴
- jinjer API 429 はテナント単位。他の大量取得と並行すると経理モードが落ちる（コード側のレート制御の有無は未確認）。
- 有給買取・手数料が jinjer 手入力で「その他」に混ざる。台帳で科目を決める。

## 宿題
- 賞与の API 入力は 2026-09-11 に実データで突合済み（9 月 FE 部賞与 30 人: 支給・厚年は行順・取引ヘッダ・支払期日 9/25 まで最終 CSV と一致、健保は支援金の品目名のみ差、支援金の検算 30 人通過）。支払期日は jinjer の支給日を正とし画面の入力欄は無し。**exe 反映は画面プレビュー（アーティファクト）の確認待ち。**
- 賞与の会社負担の丸め方は「標準賞与額×総率÷2 で 0.5 以上の端数は切り上げ」で確定（2026-09-10 谷津さん確認。エンジンの実装どおり）。2026-06 の 1 円差は経理担当側が jinjer の事業主列を使った月なので、要確認 md の一覧を見て経理担当に伝える。
