# kintai-checker

勤怠時間の突合システム。jinjer の勤怠 CSV と各部署の勤務表（Excel/PDF/画像）を突き合わせ、
**差分があるレコードを自動で検出**して Excel レポートを出力する Flask Web アプリ。

---

## 🎯 このツールの使用用途

> **対象：全部署。jinjer に登録された勤怠と、取引先・現場から届く勤務表の「ズレ」を見つけるためのツールです。**

### 何のためのツールか

各部署では、**jinjer に打刻・登録された勤怠**と、**取引先や派遣先から届く勤務表（請求勤怠）**の
2 つの記録が存在します。この 2 つは本来一致するはずですが、打刻漏れ・入力ミス・転記ミスなどで
食い違うことがあります。食い違ったまま請求・給与に進むと、**過払い／過少請求や給与計算ミス**に
つながります。

このツールは、その **2 つの記録を自動で突き合わせ（突合）、差分だけを抜き出して一覧化**します。
目視で 1 件ずつ照合していた作業を、ファイルをアップロードするだけで数分に短縮します。

### こんなときに使う

- 月次の締め前に、**jinjer の勤怠と各社の勤務表が合っているか**を確認したいとき
- 取引先から届いた勤務表（**Excel / PDF / 画像 / スキャン**）の時刻を、jinjer と照合したいとき
- **シフト記号（B・●・明 など）で書かれた勤務表**を時刻に変換して突合したいとき
- jinjer に勤怠はあるのに **勤務表が未提出の人**を洗い出したいとき
- jinjer に存在しないシフト記号について、**インポート用の新規雛形 CSV** をまとめて作りたいとき

### 何を出力するか

- 差分レポート（Excel）：行ごとに **OK / NG / 要確認 / データ欠損** を色分け判定
- 未提出者一覧
- 新規雛形 CSV（jinjer にそのままアップロード可能）

### 使ううえでの注意

- 勤務表は **Claude（AI）の OCR / 解析**で読み取ります。読み取り結果は**最終的に人の目で確認**してください（特に手書き・低画質のスキャン）。
- アップロードしたファイルや出力は**共有フォルダ上**に作られます（下記「データの置き場所」参照）。個人情報を含むため取り扱いに注意してください。
- **このツールは「気づきの補助」です。** 請求・給与へ反映する前の最終判断は必ず担当者が行ってください。

## ✨ 主な機能

| 機能 | 内容 |
|---|---|
| 勤怠突合 | jinjer CSV と勤務表ファイル（複数可）を突合、差分を OK / NG / 要確認 / データ欠損 で判定 |
| 多形式対応 | 勤務表は xlsx / xls / pdf / png / jpg / jpeg に対応（Claude Vision で OCR）|
| 未提出者検出 | jinjer に居るのに勤務表が無い人を一覧化 |
| 氏名の近似一致 🆕 | スキャンPDFのOCRが氏名を**1文字だけ誤読**しても（例: `矢野瑞穂`→`矢野瑞也`）、jinjer側に唯一の近似候補があれば自動で同一人物として突合し、jinjerの正しい氏名に寄せる。誤マッチ防止のため**4文字以上のフルネーム・編集距離1・候補が1人だけ**の場合のみ適用 |
| **シフト記号対応** 🆕 | `B = 12:30-21:00`、`● = 夜勤`、`明 = 休` のような **記号式シフト表を自動で時刻化**（凡例レビュー UI 付き）|
| **新規雛形 CSV 生成** 🆕 | jinjer 既存雛形にマッチしない記号は **インポート用 CSV を自動生成**。人間はそのまま jinjer にアップするだけ |
| **24:00跨ぎ統合** 🆕 | `4 (16:30-24:00) + a (24:00-翌09:00)` を `16:30-翌09:00` の 1 レコードに統合 |

## 👥 他の人にも使ってもらう（共有運用・ローカル同期版）

> 2026-07-02 より **ローカル同期方式** に変更。利用者向けの詳しい案内（日英併記）は
> [docs/起動方法_ローカル同期版.md](docs/起動方法_ローカル同期版.md) を参照。

`起動.bat` をダブルクリックすると、
1. NAS 上のマスター（`dist\KintaiChecker`）が更新されていれば、利用者 PC の `%LOCALAPPDATA%\KintaiChecker` へ **robocopy で差分同期**（更新なしなら比較2ファイルのみで即スキップ）
2. **ローカルの EXE** を起動（→ 起動が速い・5人同時利用OK・NAS 直接実行のロック問題なし）
3. すでに起動中なら、ブラウザを開くだけ（二重起動しない）

利用者は Python のインストール不要。**起動.bat への「ショートカット」をデスクトップに置いて使う**（bat 本体のコピーは禁止。コピーすると更新が反映されなくなる）。

### 配布側（管理者）の運用ルール

| 場面 | やること |
|---|---|
| 機能を追加した／不具合を直した | **必ず exe を再ビルド**（`kintai-exe-builder` エージェント推奨。使用中swap事故防止）して NAS の `dist\KintaiChecker` を最新化。各利用者 PC へは**次回起動時に自動同期**されるので配り直し不要 |
| 新しい人に渡す | `起動.bat` へのショートカット作成手順を案内するだけ（docs/起動方法_ローカル同期版.md 参照） |
| `.env` を更新した | NAS 直下の `.env` を書き換えるだけで、**再ビルド不要**で次回起動時に各 PC へ自動配布される（起動.bat が `.env` も同期対象にしている） |

### よくある「動かない」と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 初回起動が数分かかる | 約200MBのローカルコピー作成中（初回のみ） | そのまま待つ。2回目以降は速い |
| ブラウザが開かない | サーバー起動前にタイムアウト | ブラウザで `http://localhost:5000` を手動で開く |
| 「[WARN] Could not update the local copy」と出る | ローカル同期失敗（権限・ディスク容量等） | そのまま NAS 版で起動する（遅いが使える）。続くなら管理者へ |
| 「KintaiChecker.exe が見つかりません」と出る | NAS のマスターが未ビルド | 管理者に依頼 |
| ダブルクリックしてもブラウザが開くだけ | すでに起動中（正常動作） | そのまま使ってOK。止めたい場合は先に開いた黒い画面を閉じる |

### データの置き場所（ローカル同期版）

| フォルダ | 用途 | 扱い |
|---|---|---|
| `%LOCALAPPDATA%\KintaiChecker\uploads/` | アップロードした jinjer CSV・勤務表（処理後に自動削除） | **各利用者の PC 内**。他の人と混ざらない |
| `%LOCALAPPDATA%\KintaiChecker\uploads\sessions/` | 凡例レビュー中の中間状態（pkl） | 同上。古いものは手動削除OK |
| `%LOCALAPPDATA%\KintaiChecker\outputs/` | 突合結果 Excel など | **各利用者の PC 内**。取り出しは画面の「ダウンロード」ボタン経由（従来どおり） |

> 利用者ごとに完全分離されたため、旧方式にあった「同名ファイルの後勝ち上書き」「共有 uploads にゴミが残る」問題は解消。

## 🔄 処理フロー

### A. 直接時刻が書かれた勤務表（既存）

```
[jinjer CSV]  +  [勤務表（時刻直書き）]
   ↓                  ↓
   └──┬───────────────┘
      ▼
   突合 → Excel 出力
```

### B. シフト記号で書かれた勤務表 🆕

```
[jinjer CSV] + [勤務表（記号式）]
   ↓               ↓
   ↓          Claude API でモード判定
   ↓          → "code" モード検出
   ↓               ↓
   ↓          凡例＋シフト表 抽出
   ↓               ↓
   ↓          【凡例レビューUI】← 人間が確認・修正
   ↓               ↓
   ↓          記号 → 時刻 解決（24:00跨ぎ統合含む）
   └──┬───────────┘
      ▼
   突合 → Excel 出力
   ＋ jinjer 雛形にない記号があれば「新規雛形 CSV」も同時生成
```

## 🆕 シフト記号対応の仕組み

### 1. 自動モード判定

Claude API が勤務表を見て、以下を自動判定します：

- `direct` モード：時刻が直接書かれている（例: 9:00-17:30）
- `code` モード：記号式（例: B, ●, A/B/明, 2/4/a）+ 同じファイルに凡例あり

### 2. 凡例レビュー UI

`code` モードと判定された場合、抽出された凡例が **編集可能なテーブル** で表示されます。

| 記号 | 種別 | 出勤 | 退勤 | 休憩(分) | 休? | jinjer 雛形 |
|---|---|---|---|---|---|---|
| B | B勤 | 12:30 | 21:00 | 60 | □ | 新規雛形候補 |
| ● | 夜勤 | 16:30 | 25:00 | 60 | □ | No 38 夜帯シフト |
| 明 | 明け休 | — | — | — | ☑ | — |
| 振 | 振休 | — | — | — | ☑ | — |

- セルをクリックで直接編集できます
- 「休？」にチェックを入れるとその記号は **休扱い**
- jinjer 既存雛形にマッチした記号は **緑タグ**、しないものは **黄色タグ**で表示
- 「✅ この凡例で実行」を押すと突合へ進みます

### 3. 24:00 跨ぎ統合

連続する 2 日のシフトが 24:00 で繋がっている場合、1 レコードに統合されます。

```
田村さん:
  4日: 4 = 16:30-24:00
  5日: a = 24:00-翌09:00
   ↓ 統合
  4日: 16:30-翌09:00（実態は 33:00）
```

これは jinjer 側の打刻記録（1 シフト = 1 レコード）と整合します。

### 4. 新規雛形 CSV 生成

jinjer の既存雛形（`Z:\jinjer移行\カレンダー\スケジュール雛形一覧_*.csv`）と照合し、
マッチしない記号があれば **インポート用 CSV** を自動生成します。

```csv
No,勤怠スケジュール名称,略称(3文字以内),勤怠スケジュール名ID,予定区分,休日ID,出勤時刻(0:00~47:59),退勤時刻(0:00~47:59),...
56,B勤,B,B,9998,1,12:30:00,21:00:00,...
```

このまま jinjer にアップロードできます。

### 5. API直接投入（既定ルート・2026-07追加）

グリッドCSV生成後、画面には **🚀 APIでjinjerへ直接投入** ブロックが表示されます。
jinjer画面の月次スケジュールCSVインポートは一部従業員にサイレントに反映されない
事象があるため（2026-07に11名で実測）、**API投入が標準ルート**です。
生成されたグリッドCSVは控え・監査用で、画面からのアップロードは行いません。

1. **① 差分プレビュー** — jinjerの現状を取得し「誰の何日をどう変えるか」を表示
   （書き込みなし）。承認用Excelも出力されます
2. **② この内容で投入** — 差分がある日だけ書き込み、反映を1行ずつ自動検証
3. 「要手動確認」に出る項目（休日に予定残存＝画面から手動削除、休暇登録日など）は
   レポートの指示に従って個別対応

コマンドラインからも同じ処理ができます（作成済みグリッドCSVの再投入）:

```bash
python schedule_import_run.py <グリッドCSV|フォルダ>... --month 2026-08            # dry-run
python schedule_import_run.py <グリッド...> --month 2026-08 --execute --expect 123  # 投入＋検証
```

詳細設計: `docs/PLAN_スケジュールAPI投入.md`
