# kintai-checker

勤怠時間の突合システム。jinjer の勤怠 CSV と各部署の勤務表（Excel/PDF/画像）を突き合わせ、
**差分があるレコードを自動で検出**して Excel レポートを出力する Flask Web アプリ。

## ✨ 主な機能

| 機能 | 内容 |
|---|---|
| 勤怠突合 | jinjer CSV と勤務表ファイル（複数可）を突合、差分を OK / NG / 要確認 / データ欠損 で判定 |
| 多形式対応 | 勤務表は xlsx / xls / pdf / png / jpg / jpeg に対応（Claude Vision で OCR）|
| 未提出者検出 | jinjer に居るのに勤務表が無い人を一覧化 |
| **シフト記号対応** 🆕 | `B = 12:30-21:00`、`● = 夜勤`、`明 = 休` のような **記号式シフト表を自動で時刻化**（凡例レビュー UI 付き）|
| **新規雛形 CSV 生成** 🆕 | jinjer 既存雛形にマッチしない記号は **インポート用 CSV を自動生成**。人間はそのまま jinjer にアップするだけ |
| **24:00跨ぎ統合** 🆕 | `4 (16:30-24:00) + a (24:00-翌09:00)` を `16:30-翌09:00` の 1 レコードに統合 |

## 👥 他の人にも使ってもらう（共有運用）

このフォルダ自体を `Z:\勤怠チェックシステム\kintai-checker\` 配下の **ネットワーク共有** に置いておけば、
利用者は Python のインストール不要で、**起動.bat をダブルクリックするだけ** で使えます。

### 利用者向け手順

1. エクスプローラーで `Z:\勤怠チェックシステム\kintai-checker\起動.bat` を開く
   - よく使うなら、**起動.bat を右クリック →「ショートカットを作成」→ ショートカットをデスクトップへ** 置くと便利
2. 黒い画面（コマンドプロンプト）が立ち上がり、数秒〜数十秒で既定のブラウザに `http://localhost:5000` が開く
3. 終わったら **黒い画面を ×（閉じる）でクローズ**。サーバーも一緒に止まる

### 配布側（管理者）の運用ルール

| 場面 | やること |
|---|---|
| 機能を追加した／不具合を直した | **必ず `build_exe.bat` を再実行** して `dist\KintaiChecker\KintaiChecker.exe` を最新化する。古い EXE のまま放置すると、利用者は古い動作のままになる |
| 新しい人に渡す | このフォルダのパス（または `起動.bat`）を共有するだけ。インストール作業は不要 |
| `.env` を更新した | `.env` は EXE に同梱されるので、`build_exe.bat` を再実行しないと反映されない |

### よくある「動かない」と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 黒い画面が一瞬で消える | ポート 5000 が他のアプリ（別の Flask アプリ等）で使われている | 他のアプリを閉じてからもう一度 起動.bat を実行 |
| 起動.bat を叩いてもブラウザが開かない / 「サーバーに接続できません」 | 初回起動でネットワーク共有から DLL を読み込んでいる最中 | **最大 1 分** 待つ。それでも開かなければブラウザで `http://localhost:5000` を手動で開く |
| 「KintaiChecker.exe が見つかりません」と出る | 管理者がまだ `build_exe.bat` を実行していない | 管理者に依頼 |
| 動作がやたら遅い／時々起動が失敗する | ネットワーク経由の DLL ロードが不安定 | 共有フォルダごと自分の PC のローカル（例: `C:\KintaiChecker\`）にコピーして、そちらの `起動.bat` を使う |

### データの置き場所

| フォルダ | 用途 | 共有運用での扱い |
|---|---|---|
| `uploads/` | 利用者がアップロードした jinjer CSV・勤務表（処理後に自動削除） | **共有フォルダ上に作られる**。原則自動削除されるが、異常終了時は残る |
| `uploads/sessions/` | 凡例レビュー中の中間状態（pkl） | 同上。古いセッションは手動削除でOK |
| `outputs/` | 突合結果 Excel・新規雛形 CSV・jinjer 投入用 CSV | **共有フォルダ上に作られ、誰でも参照可能**。ファイル名にタイムスタンプが入る |

> 注: 同じ秒に 2 人が同時に出力すると、ファイル名が衝突して **後勝ち（上書き）** になる可能性があります。
> 同時利用が多い時間帯は気をつけてください（実用上ほぼ起きません）。

## 🔄 処理フロー

### A. 直接時刻が書かれた勤務表（既存）

```
[jinjer CSV]  +  [勤務表（時刻直書き）]
   ↓                  ↓
   └──┬───────────────┘
      ▼
   突合 → Excel 出力
```

### B. シフト記号で書かれた勤務表 🆕

```
[jinjer CSV] + [勤務表（記号式）]
   ↓               ↓
   ↓          Claude API でモード判定
   ↓          → "code" モード検出
   ↓               ↓
   ↓          凡例＋シフト表 抽出
   ↓               ↓
   ↓          【凡例レビューUI】← 人間が確認・修正
   ↓               ↓
   ↓          記号 → 時刻 解決（24:00跨ぎ統合含む）
   └──┬───────────┘
      ▼
   突合 → Excel 出力
   ＋ jinjer 雛形にない記号があれば「新規雛形 CSV」も同時生成
```

## 🆕 シフト記号対応の仕組み

### 1. 自動モード判定

Claude API が勤務表を見て、以下を自動判定します：

- `direct` モード：時刻が直接書かれている（例: 9:00-17:30）
- `code` モード：記号式（例: B, ●, A/B/明, 2/4/a）+ 同じファイルに凡例あり

### 2. 凡例レビュー UI

`code` モードと判定された場合、抽出された凡例が **編集可能なテーブル** で表示されます。

| 記号 | 種別 | 出勤 | 退勤 | 休憩(分) | 休? | jinjer 雛形 |
|---|---|---|---|---|---|---|
| B | B勤 | 12:30 | 21:00 | 60 | □ | 新規雛形候補 |
| ● | 夜勤 | 16:30 | 25:00 | 60 | □ | No 38 夜帯シフト |
| 明 | 明け休 | — | — | — | ☑ | — |
| 振 | 振休 | — | — | — | ☑ | — |

- セルをクリックで直接編集できます
- 「休？」にチェックを入れるとその記号は **休扱い**
- jinjer 既存雛形にマッチした記号は **緑タグ**、しないものは **黄色タグ**で表示
- 「✅ この凡例で実行」を押すと突合へ進みます

### 3. 24:00 跨ぎ統合

連続する 2 日のシフトが 24:00 で繋がっている場合、1 レコードに統合されます。

```
田村さん:
  4日: 4 = 16:30-24:00
  5日: a = 24:00-翌09:00
   ↓ 統合
  4日: 16:30-翌09:00（実態は 33:00）
```

これは jinjer 側の打刻記録（1 シフト = 1 レコード）と整合します。

### 4. 新規雛形 CSV 生成

jinjer の既存雛形（`Z:\jinjer移行\カレンダー\スケジュール雛形一覧_*.csv`）と照合し、
マッチしない記号があれば **インポート用 CSV** を自動生成します。

```csv
No,勤怠スケジュール名称,略称(3文字以内),勤怠スケジュール名ID,予定区分,休日ID,出勤時刻(0:00~47:59),退勤時刻(0:00~47:59),...
56,B勤,B,B,9998,1,12:30:00,21:00:00,...
```

このまま jinjer にアップロードできます。
