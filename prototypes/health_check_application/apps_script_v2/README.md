# 健康診断申込 Apps Script v2（年度別スプレッドシートに紐づける版）

Operation Hub の健診申込モード（`services/health_apply/`）と同じシート構成・列並びで動く本番用スクリプト。
試作 v1（`../apps_script/`）は3名固定・選択肢ベタ書きだったが、v2 は **設定・選択肢・対象者・回答・監査ログ**
の5シートを読み、選択肢（健診機関50件＋その他／健診種別6件／婦人科検診／続柄）はシートから作る。

## 役割分担

| 誰が | 何を |
|---|---|
| Hub（対象者登録） | 対象者シートの 1〜14列（年度・社員番号・氏名・社用メール・在籍区分・前年度情報・登録日時・登録者）を追記 |
| このスクリプト | 案内メール送信（トークン生成・15列以降）、個別URLの表示、回答の追記、再回答の許可、監査ログ |
| Hub（回答読込） | 回答・対象者を読んで集計・検証（jinjer には書かない） |

## 導入手順（谷津さん）

1. 年度のスプレッドシートを開き、拡張機能 → Apps Script で **コンテナにバインドされた**プロジェクトを作る。
2. `Code.gs`・`Index.html`・`appsscript.json`（プロジェクト設定で「マニフェストを表示」）を貼る。
3. スプレッドシートを開き直すとメニュー「健康診断申込」が出る → **「シートを初期化」** を実行
   （5シートとヘッダー、コード列の書式なしテキスト、設定シートのキー一覧ができる）。
4. 設定シートを埋める（`スキーマ版` は `2027.1` のまま。年度・前年度・受付開始/終了・受診期間・回答受付=1・
   案内メール件名/本文・担当者連絡先）。選択肢シートに hpm.txt を貼る（`docs/PLAN_健診申込モード.md` の手順）。
5. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、実行ユーザー「自分」、アクセス「全員」。
   出てきた `/exec` の URL を設定シートの `WebアプリURL` に入れる。
6. Hub で対象者を登録した後、メニュー「案内メールを送る（未送信のみ）」→ 確認語 `SEND {年度} {人数}`。
   送信元は実行ユーザー（admin@nmht.co.jp で実行する前提。別名で送るなら MailApp の `from` に
   Gmail の送信エイリアスを設定する。**要確認**）。

## 挙動の要点

- 個別URL `…/exec?token=…` のトークンは送信時に生成し、シートには **SHA-256 のハッシュだけ**を置く。
  再送は作り直し（古いURLは無効）。
- `doGet` は設定が揃っていない／受付期間外／`回答受付=0` のときは案内ページだけ返す。
  有効なURLの初回表示で `初回アクセス日時` を1回だけ記録する（メールのセキュリティ検査でも付くので、
  本人が見た証拠にはしない）。
- 回答は `申込状態` が `送信済` か `再回答待ち` のときだけ受け付け、`回答` シートへ **追記**（回答版+1、
  受付番号 `HC-{年度}-{社員番号}-{版2桁}`）。対象者の `申込状態=回答済`・受付番号・回答版・回答日時を更新。
- 画面からは選択肢の**コード**だけを受け取り、表示名はシートから引く。本人特定はトークンだけで行い、
  画面から来た社員番号などは使わない。
- 「前年度と同じ」は対象者行の前年度3コードを写す。`前年度情報元=なし` の人は選べない。
- 訂正は担当者がメニュー「選択した行の再回答を許可」（`再回答待ち`）→ 本人が同じURLから再回答。
- 日時はすべて `yyyy-MM-dd'T'HH:mm:ss` の文字列で書く（Hub 側の読み取りと揃える）。

## テスト

`tests/test_health_apply_apps_script.py` が node で `Code.gs` を読み、Hub の列定義と一致すること、
ハッシュ・受付期間・回答の検証・回答行の組み立てを検査する。
