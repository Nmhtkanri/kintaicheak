# 差異一覧 工数削減プラン（横レイアウト改善＋トリアージ＋グループ単位1画面）

作成: 2026-06-18 / ステータス: **計画（未実装）**。実装は承認後に着手する。

---

## 背景・課題

派遣会社の月次勤怠突合。請求勤怠は **6種類（NMHT/iTone/Fieldglass/e-staffing/PDF/ERCSTS）**、対象 **100人以上**。
ヒアリングで判明した二大ボトルネックと制約：

- **① jinjerからのDL（汎用データ 6本以上）** … 客先・到着がバラバラ、請求先も従業員ごとに違うため **グループ単位の逐次処理は意図的**（一気見はExcelスクロールでミスが出やすい）。集計列（総労働/休憩/休暇）も見るため汎用データは必要。書き戻し(手順3)にも使う。
- **② 差異の目視判断（300〜400件）** … 判断方針は **「基本は請求勤怠を正、打刻時/打刻修正のコメント次第でjinjerを正」**＝**コメントが判断の分かれ目**。
- **横スクロール問題** … 差異一覧が約26列あり、1件判断するのに左右へ振られてミスの元。

### 方針（合意済み）
- 小分け（グループ単位）処理は**維持**。"全件1発"はしない。
- **横（列）と縦（行）の両方**でスクロールを減らす。
- 判断は **既定=請求勤怠**、コメント/DANGER/未マッチだけ人が見る。
- 汎用データDLは現状維持（将来P6でAPI書き戻しにすれば往復ゼロも可）。

## 機能1: 差異一覧の列レイアウト改善（横スクロール解消）

**ねらい**: 「1件を判断するのに必要な列」を左に集約＋識別列を枠固定し、横スクロールなしで判断完結。

### 新しい列順（左→右。代表案、実装時に微調整）
| 区分 | 列 |
|---|---|
| **識別（ウィンドウ枠固定）** | 氏名 / 対象日付 / 差異種別 |
| すぐ見る | 請求勤怠値 / jinjer値 / 差分(分) / 警告レベル |
| トリアージ | **トリアージ区分**（機能2で追加） |
| 判断の根拠（人間判断の左にまとめる） | **打刻時コメント** / **打刻修正時コメント** / 警告理由 |
| 判断（入力） | 人間判断 / 判断メモ |
| 反映（手入力・普段使わない） | 自動修正提案値 / 打刻修正 / 手入力休憩1 / 手入力復帰1 / 手入力休憩時間 |
| 参考（右端・普段見ない） | 出勤予定 / 退勤予定 / 休憩予定 / 休日休暇名1 / 休日休暇名1：種別 / 実績確定状況 / 従業員ID / 行ID / 元突合結果ファイル |

→ 先頭の約12列だけで判断完結。`氏名/対象日付/差異種別` を **freeze_panes** で固定（右に行っても誰の行か見失わない）。

### コメント列の構成（2列・人間判断の左へ）
コメントは**判断の材料**なので、**人間判断より左**に隣同士で置く（横スクロールせず「読む→決める」）。
- **打刻時コメント**（新規）… 汎用データの「打刻時コメント」列(#96)から転記。実データはこの列が `出勤: ○○ , 退勤: ○○` 形式で**出勤・退勤の打刻時コメントを両方含む**（例: `出勤: KDX出社のため、10:00時差出勤 , 退勤: `）。**APIではなく汎用データから転記**するので申請データCSVモードでも常に表示される（＝「CSVモードで打刻時コメントが消える」現象の解消）。
- **打刻修正時コメント**（既存・申請データCSV由来）… 前回は手入力「打刻修正」の隣だったが、**人間判断の左**へ移す。打刻修正(手入力)は普段使わないので右側でよい。

### 変更ファイル
- `quick_compare.py`: `DIFF_COLUMNS` の並べ替え、`write_excel` で `ws.freeze_panes`（識別3列の右）設定、`width_map` 調整。
- `JINJER_EXTRA_COLUMNS` に「打刻時コメント」を追加（汎用データ#96から転記。有休・休日休暇名と同じ転記の仕組み）。DiffRow / extra / write_excel に列追加。
- 参考列が多すぎる場合は「差異一覧」本体から外し別シート化も検討（要相談）。
- `quick_export.py` は**列名で読む**ため列順変更に影響なし（後方互換）。
- テスト: 列順・freeze・打刻時コメント転記・必須列の存在を検証。

### 工数: 約0.5〜1日（低リスク）

## 機能2: トリアージ（縦＝判断件数を激減）

**ねらい**: 300〜400件を仕分け、**人が見るのは「要確認」だけ**に。既存のコメント列が要確認の根拠になる。

### 仕分けルール（設計書 P1 §4.7 に準拠）
- **要確認 (needs_check)** — 人が読む:
  - 打刻時コメント or 打刻修正申請の理由がある（jinjer正の例外候補）
  - DANGER（労基: 勤務6h超で休憩0:00 等）
  - 氏名が fuzzy/未マッチ（confidence < 1.0）
  - 総労働・休憩の差が大きい（閾値超）
- **自動OK (jinjer勤怠) — 全日休暇**:
  - **出勤・退勤が0（打刻なし）＆ 休日休暇名1に値あり ＆ 休日休暇名1：種別 = "全日"** → 全日休暇で打刻無しが正常なので、**人間判断 = "jinjer勤怠"(OK)** を自動セット。
  - 種別の実値は「全日 / AM有休 / PM有休」（"全日" のみ対象。AM/PM の半休は要確認に残す）。
- **自動採用 (auto_fix_candidate)** — 既定で請求勤怠を正:
  - 上記以外の出勤/退勤差異（コメント無し・氏名確実・差分が妥当）
  - 既定の「人間判断」に **請求勤怠** を自動セット（人は確認して一括承認、または既定のまま手順3へ）

### 見せ方
- 「差異一覧」に **トリアージ区分** 列を追加。
- **要確認を上**に並べ替え、自動採用は下 or 別シート「自動採用候補」へ（縦スクロール減）。
- サマリーに「要確認件数 / 自動採用件数」を表示。

### 既定判断の安全策
- 自動採用に既定「請求勤怠」を入れても、**手順3は従来どおり人間判断列を読む**ので、人がゼロチェックで投入されることはない（DANGER は必ず要確認に回す）。

### 変更ファイル
- 新規 `services/triage.py`（差異行→区分判定、純粋関数）。
- `quick_compare.py`: DiffRow に区分/既定判断、`compute_diffs` で区分付与、`write_excel` で並べ替え・シート分割・サマリー。
- テスト: `tests/test_triage.py`（各条件の分類）、quick_compare 統合。

### 工数: 約2〜3日

## 機能3: グループ単位の「1画面で差異一覧」（手順1+2連結）

**ねらい**: グループ単位は維持しつつ、手順1の「1ファイルずつ」をやめ、突合結果xlsxの手動受け渡しも廃止。

### フロー
1画面で **そのグループの請求勤怠（フォルダ or 複数ファイル）＋ 汎用データCSV ＋ 申請データCSV（共通・使い回し）＋ 対象月** を指定 → 内部で 手順1（突合, 形式は自動判定）→ 手順2（差異一覧＋トリアージ）を実行 → 差異一覧xlsx 出力。

- 突合結果xlsx は内部一時生成（ユーザーは触らない）。
- 氏名が解決できなかった人は **「未マッチ一覧」シート**に出し、そこだけ手当て。
- グループはまたがない（複数グループは従来どおり別々に実行）。

### 変更ファイル
- `app.py`: 新ルート（または既存 `/quick_compare` 拡張）で請求勤怠フォルダ/複数ファイル＋汎用データ＋申請データ＋月を受け、突合→差異一覧を一括。
- `templates/index.html`: 入力欄を1画面に集約。
- 既存 `match()` / `parse_timesheet_smart()` / `run_quick_compare()` を流用（突合結果の中間ファイルを内部生成）。

### 工数: 約2〜3日

## 触らないもの・前提
- **汎用データDLは現状維持**（集計列の表示＋手順3の書き戻しテンプレに必要）。本プランでは削減しない。

- 既存の差異一覧/突合結果フォーマットとの**後方互換**（quick_export は列名読み）。
