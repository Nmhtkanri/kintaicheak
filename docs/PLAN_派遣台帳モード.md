# 派遣台帳モード 設計メモと検証記録（2026-08-28 実装）

派遣元管理台帳の四半期作成（①鮮度チェック→②build＋警告トリアージ→③PDF→④jinjer添付）を
ハブの5つ目のモードとして実装した記録。発端は `Z:\API連携\派遣元管理台帳\モード化引き継ぎ.md`。

## 決めごと（2026-08-28 谷津さん確定）

1. **添付はデタッチ子プロセス**（launcher.py の `--daicho-attach` 分岐／python は
   `daicho_attach_run.py`）。exeのコンソール窓を閉じても走り続ける。
   「今夜回す」は子プロセス内で 22:00（`HAKEN_ATTACH_TONIGHT_AT`）まで待機し、
   スリープは `SetThreadExecutionState` で抑止。schtasks は使わない。
   デタッチが環境に阻まれたら `.env` に `HAKEN_ATTACH_FALLBACK_THREAD=1` でスレッド実行へ切替
2. **警告トリアージは表示＋前回比のみ**（確認済みの台帳保存はしない）。build 前の警告CSVと
   (区分,契約No,氏名,内容) 完全一致で突合し 新規/継続/解消 を出す。解消手段は元データ修正→再build
3. **標報投入との相互ロック**: 添付側は `SHAHO_IMPORT_LOCK_FILE` を見て15分間隔で待機、
   標報投入側（shaho_writer.acquire_lock）は `HAKEN_ATTACH_LOCK_FILE` を見て止まる

## 構成

- コア: `services/daicho/`（2026-08-28 に `Z:\API連携\派遣元管理台帳` から移設。
  旧側は `python -m daicho` の互換ラッパのみ。経理モードと同じ「本体はハブ」の型）
- jinjer クライアント: `services/daicho/hub_client.DaichoAttachClient` が
  `services/jinjer_api_client.JinjerWriteClient` へ橋渡し。429を180秒×10回粘る
  `_write_with_retry` と403トークン失効→再認証は jinjer_attach 側に温存（二層）
- データ: `Z:\派遣元管理台帳\`（環境変数 `DAICHO_DATA_ROOT`）。進捗JSON・添付ログも同所
- ルート: app.py 末尾の「派遣元管理台帳モード」帯（/haken_*）。UI は index.html の
  `haken-card` 1枚＋script.js 末尾（インラインscript禁止）

## Phase 1 検証（移設の同一性）

- 2025Q3 を移設前後のCLIで build → 一覧CSV・警告CSVが**バイト一致**（168枚・警告50件）
- jinjer人マスタAPI: 新旧クライアントで362人・全項目一致
- 添付のデタッチ通し: `--limit 1` で子プロセス起動→jinjer照合→添付済みskip→done→ロック解放
  （書き込みゼロで配管のみ実証）。実PDF出力は 2025Q3 168枚を約5分で再生成

## Phase 2 検証（FG新レポートパーサ）

新レポート: ユニアデックスXLSX（66列・2行目ヘッダー・WO×改訂×CC重複・210改訂/108人）と
エリクソンCSV（47列・重複ヘッダー6組・3人）。実サンプルで確認した要点:

- **「最新の作業オーダー終了日」は改訂共通の最新値** → 次改訂の開始日−1日へ切り詰めて
  過去改訂の期間を復元（切り詰め後、2026Q2 の選択は旧CSVと同じ100件・期間差分ゼロ）
- 終了日が空の改訂が 1/210 件（即日終了のWO）→ 継続中扱いになるため build が警告を出す
- エリクソンはWO・期間列が無い（足すと行が全滅する）→ 台帳行は手入力マスタのまま、
  責任者・指揮命令者・就業時間等を現行値で上書き。突合は Job Seeker ローマ字と
  マスタの氏名/氏名カナのトークン照合（カナ列にFG表記のローマ字を入れる運用）

**新旧比較（2026Q2 を fg-mode=legacy / auto で build して一覧CSVを diff）:**

- 回帰: 2025Q3 legacy は移設時出力と**バイト一致**（Phase 2 変更が旧経路に影響しないこと）
- 2026Q2: 両モードとも 171枚（e-staffing 47 / FG 100 / 直接 24）で行の増減なし
- セル差分 874箇所/103行 — **全件説明可能**（(c)未説明ゼロ）:
  - 指揮命令者 103件: Supervisor Info の役職付き5点（旧はWO列の氏名のみ）
  - 派遣先責任者/苦情申出先 101/100件: レポートの現行5点（旧details JSONより新しい）
  - 組織単位 100件: Division Name UAL 表記＋組織の長の職名
  - 便宜供与 99件・所在地/就業場所 99/38件: Work Location UAL の現行値
  - 休日備考 45件・業務内容 14件: レポートの remarks / Description of Work
  - エリクソン3行: 指揮命令者・責任者・休日等の現行値化（レポートはローマ字表記）
  - 契約期間 1件: 上記「終了日が空」のWO（警告で人に見せる）
