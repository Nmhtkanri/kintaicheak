# PLAN: スケジュールアップロードモードに jinjer API 直接投入を組み込む

**作成日**: 2026-07-13
**背景**: jinjer画面の月次スケジュールCSVインポートが一部従業員にサイレントに反映されない
（2026-07: 11名で実測。調査_7月6日法休化と未来打刻_20260710.xlsx「7月シフト未反映の疑い」）。
手順③のAPI投入（docs/PLAN_手順3_API直接投入.md）と同じ思想で、スケジュール登録もAPI経路を既定にする。
実証元: `Z:\API連携\scripts\reinject_july_grid_schedules.py`（11名159行のドライランで方式確認）。

## 1. 決定事項（2026-07-13 谷津さん確定）

1. **API投入を既定ルート化**。グリッドCSVの生成・ダウンロードは控え・監査用に残す
2. **書込は差分のみ**。jinjerの現状を取得し、シフト表と食い違う日だけ書く。
   投入前に差分プレビュー（誰の何日をどう変えるか）→ 承認 → 投入 → 自動検証
3. **CLIも用意**。作成済みグリッドCSV＋対象月を指定して画面を通さず投入できる

## 2. 構成

```
[Web] シフト表解析 → /export_jinjer_csv → グリッドCSV生成（従来どおり・監査物）
        → #sched-api-area「🚀 APIでjinjerへ直接投入」
        → ①差分プレビュー(dry-run) → fingerprint → ②投入(execute)
        → POST /schedule_api_import（ジョブ）→ GET /api_import_status/<job_id>（手順③と共用）
[CLI] python schedule_import_run.py <グリッドCSV|フォルダ>... --month YYYY-MM
      （投入は --execute --expect <行数> 必須）
[中核] services/schedule_import_runner.py  run_schedule_api_import()
        1. グリッドCSV読込（年月ヘッダー検証・NFKC正規化・複数ファイルマージ）
        2. スケジュール雛形一覧CSV（Config自動解決）で 雛形ID→出勤/退勤/休憩予定を解決
           未知セル値は投入前に中止（新規雛形の登録を案内）
        3. jinjer現状取得: work-schedules（同一日二重返却は先頭採用）/
           requested-day-offs（休暇日ガード）/ affiliations→月末時点の打刻グループ
        4. 差分プラン: 一致は書かない。休みセル×予定残存は「要手動削除」
           （休暇登録があれば「削除しないで確認」= 半休の誤削除防止）
        5. execute時: プラン再計算→fingerprint一致ガード→194列CSV（4900行分割）→
           POST /v1/kintai-imports 種別5 → ポーリング（手順③と共通実装）→
           反映検証（休憩なし雛形は現物も休憩なしまで厳密比較）→ Excelレポート
```

## 3. 手順③との違い（重要な設計判断）

| 論点 | 手順③ (kintai_import_runner) | スケジュール (schedule_import_runner) |
|---|---|---|
| 未来月 | 無条件NG（過去修正用・D/M/Y事故防止） | **許可**（翌月登録が本命）。代替ガード=month明示必須＋グリッド年月一致＋日付自前生成 |
| 休暇ガード | CSVの休暇列（休日休暇名1等） | **requested-day-offs API**（グリッドに休暇列が無い） |
| 検証 | compare_row（CSV空欄=無検証） | **verify_plan_rows**（日丸ごと置換のため期待休憩なし→現物なしまで検証） |
| 共有 | poll_import_status / post_kintai_import / MAX_ROWS_PER_IMPORT / ジョブ辞書・ロック（同時予約1件がモード横断で効く） | 同左 |

## 4. 実データで確認済みの癖（テストで固定）

- 同一日の**新旧二重返却は先頭が新**（get_work_schedules を先頭採用に修正。従来は後勝ち=旧を拾うバグ）
- `*打刻グループID` は既存スケジュール行のstoreではなく**所属履歴（affiliations）の現行グループが正**
  （能美2024047・及川2025010: 誤上書きレイヤー=40、正=43 を実測）
- 手作りグリッドの表記ゆらぎ: **全角雛形ID（'１'）→NFKC正規化**、**'0'セル=明け休扱い**
  （KDX 140-160・UAL時給制の2026-07実データ）
- executor に勤怠管理者権限が無い社員番号を指定すると**サイレント破棄**（手順③の実測を踏襲、既定は未指定）
- API取得は429が出ることがある → _with_retry（8秒×試行数バックオフ）

## 5. 運用

- 通常: スケジュールアップロードモードで解析 → CSV生成後に ①差分プレビュー → 内容確認 → ②投入
- 「要手動確認」シートの区分:
  - **休日に予定残存** … APIでは削除不可。jinjer画面から手動削除
  - **休暇登録日（削除しないで確認）** … 半休の予定の可能性。消す前に本人の休暇申請を確認
  - **休暇登録日スキップ** … jinjerが書込を無視するため投入せず（対応不要のことが多い）
  - **検証NG / インポート失敗** … 要調査・再実行
- 再発対応（画面を通さない再投入）: `python schedule_import_run.py <グリッドCSV...> --month YYYY-MM`
- **jinjer画面からの月次スケジュールインポートは併用しない**（API投入に一本化）
