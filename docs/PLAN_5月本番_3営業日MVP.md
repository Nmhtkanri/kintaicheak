### 2.1 `quick_merge.py`

**目的**: 既存 kintai-checker が出力した複数の `突合結果_*.xlsx` を 1 冊にまとめ、差異あり行を並べる。

**入出力**:
- 入力: `Y:\給与明細\R8年\5月\突合結果\*.xlsx`（既存 kintai-checker 出力）
- 出力: `Y:\給与明細\R8年\5月\差異一覧_2026-05.xlsx`

**シート構成**:

| シート名 | 内容 |
|---|---|
| サマリ | ファイル数・総行数・差異件数・未判断件数・承認/却下/保留 件数 |
| 差異一覧 | 1行 = 1差異、人間判断プルダウン付き |
| 取込ログ | 集約時にエラーになったファイルや行の記録 |

**「差異一覧」シートの列**:

| 列 | 内容 |
|---|---|
| 行ID | 一意キー（連番）|
| 社員番号 | jinjer 従業員IDと一致 |
| 氏名 | 表示用 |
| 対象日付 | YYYY-MM-DD |
| 差異種別 | 勤務時間 / 休憩時間 / 実働時間 など |
| 請求勤怠値 | 分または HH:MM |
| jinjer値 | 分または HH:MM |
| 差分(分) | jinjer - 請求勤怠 |
| 自動修正提案値 | 請求勤怠値をそのまま入れる（承認時にCSVへ書く値）|
| **人間判断** | 空欄 / 承認 / 却下 / 保留（Excel データ検証プルダウン）|
| **判断メモ** | 任意記入 |
| 元ファイル | 突合結果xlsx のファイル名 |

triage（auto_fix_candidate / needs_check 分類）は **やらない**。全行を人間が見る前提。

**実装ポイント**:
- `Z:\API連携\create_template.py` の openpyxl パターン流用（データ検証プルダウン・auto_filter・色塗り）
- 文字コードは xlsx なので意識不要

**工数**: **2〜3 時間**（5/27 水 AM）

### 2.2 `quick_export.py`

**目的**: 差異一覧シートで承認された行を抽出し、jinjer ダウンロード CSV をベースに該当セルだけ上書きしたアップロード用 CSV を生成。

**入出力**:
- 入力1: `Y:\給与明細\R8年\5月\差異一覧_2026-05.xlsx`（人間判断列が埋まっている）
- 入力2: `Y:\給与明細\R8年\5月\jinjer_download_2026-05.csv`（jinjer 管理画面から事前ダウンロード、CP932、194列）
- 出力: `Y:\給与明細\R8年\5月\jinjer_upload_2026-05.csv`（CP932）

**処理**:

```
1. 差異一覧シートを読み、「人間判断 = 承認」の行を集める
2. ダウンロード CSV を読む（cp932、194 列）
3. 承認行ごとに:
   - 従業員ID × 年月日 で CSV の該当行を特定
   - 差異種別に応じて該当列だけ請求勤怠値で上書き
     - 「勤務時間」差異 → 出勤1（22列目）/ 退勤1（23列目）を上書き
     - 「休憩時間」差異 → 休憩1（42列目）/ 復帰1（43列目）を上書き
     - 「実働時間」差異 → 機械判定不能、警告して人手対応
4. 上書きされた行だけを別 CSV として出力
5. dry-run → --execute で本ファイル書き出し
```

**dry-run 出力例**:
```
[dry-run] 承認 23 件 / 却下 5 件 / 保留 2 件 / 未判断 1 件
[dry-run] 上書き対象: 23 行
[dry-run] 警告: 「実働時間」差異 3 件は自動修正不可、手動で CSV 編集が必要
[dry-run] 出力先: Y:\給与明細\R8年\5月\jinjer_upload_2026-05.csv (--execute 指定で書き出し)
```

**実装ポイント**:
- `Z:\API連携\update_salary_unit_prices.py` の dry-run → 本番フロー踏襲
- CP932 入出力に注意（`encoding='cp932'`）

**工数**: **半日**（5/27 水 AM〜PM）
