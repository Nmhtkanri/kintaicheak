# 健康診断申込モード 設計メモと検証記録（2026-09-02 着手）

2027年度の健康診断申込を、Googleアカウント不要の個別URL（Apps Script Webアプリ）で社員から集め、
年度別のGoogleスプレッドシートに貯める。Operation Hub は **対象者登録** と **回答読込** を担当し、
jinjer には書かない（jinjer 登録は次段階・別承認）。発端は Codex の試作
`prototypes/health_check_application/`（2026-09-01）と、谷津さんの「健診機関・健診種別をHPMコード付きの
プルダウンにしたい」という要望。

## 決めごと（2026-09-02 谷津さん確定）

1. **健診種別は HPM コード 6件のプルダウン1つ**（10 定期健康診断／11 人間ドックA／12 人間ドックB／
   13 人間ドックC／14 雇用時の健康診断／15 人間ドック1日コース）。試作の「健診オプション」チェック群は
   廃止し、HPM コードに無い **「婦人科検診」だけ追加検査のチェック** で残す。
2. **健診機関は HPM 場所コード付きの 50件＋「その他」** で試作の8件を置き換える。
3. **選択肢マスタの正本は Google の「選択肢」シート**。Apps Script が画面を作り、Hub は検証に読む。
   Hub はこのシートに書かない。
4. **着手順は Hub 側から**: ①Hub 回答読込 → ②Hub 対象者登録 → ③Google 側（Apps Script v2）。
5. Hub の Google への書き込みは **「対象者」「監査ログ」への追記だけ**（`sheets_gateway` が構造で止める）。
6. 読み込んだ個人情報はレスポンスに載せるだけで、サーバ・共有フォルダ・永続キャッシュに置かない。

## 構成

- コア: `services/health_apply/`（パッケージ。`build_exe.bat` は `--collect-submodules`）
  - `schema.py` シート名・列名・スキーマ版の正本（`SCHEMA_VERSION = "2027.1"`）
  - `options.py` 「選択肢」シートの解釈（コードは文字列のまま。「別名」列で jinjer 表記をコードへ寄せる）
  - `settings.py` 年度設定JSON（NAS）と鍵JSONの所在
  - `access.py` 利用許可CSV（読めなければ誰も使えない）
  - `sheets_gateway.py` Sheets API v4（google-auth の AuthorizedSession。関数内 import）
  - `responses.py` 対象者×回答の突合・集計（純粋関数）
- ルート: `app.py` 末尾の「健康診断申込モード」帯（`/health_apply_*`）。差替え点は
  `health_apply_gateway`（Sheets）と、②で足す jinjer 取得関数。
- 画面: `templates/index.html` の `ha-card` 1枚（id は `ha-` 接頭辞）＋ `static/script.js` 末尾の `ha*` 関数。
  インライン script には書かない。
- 設定（`config.py`）:

| 名前 | 既定 | 用途 |
|---|---|---|
| `HEALTH_APPLY_ALLOWED_USERS_CSV` | `Z:\API連携\docs\健診申込_閲覧許可ユーザー.csv` | 列: ユーザー名, 表示名, 備考。画面も API もこれで止める |
| `HEALTH_APPLY_SETTINGS_JSON` | `Z:\API連携\docs\健診申込_年度設定.json` | 年度→スプレッドシートID・WebアプリURL |
| `HEALTH_APPLY_SERVICE_ACCOUNT_JSON` | `%LOCALAPPDATA%\KintaiChecker\health_apply\service_account.json` | 健診専用サービスアカウントの鍵。**管理者PCのローカルのみ** |
| `HEALTH_APPLY_SESSION_DIR` | `%LOCALAPPDATA%\KintaiChecker\health_apply_sessions` | 対象者プレビューの一時保持（②） |
| `HEALTH_APPLY_PREVIEW_TTL_HOURS` | 2 | プレビューの有効時間 |

年度設定JSONの形:

```json
{"schema": 1, "default_year": "2027",
 "years": {"2027": {"spreadsheet_id": "1AbC...", "webapp_url": "https://script.google.com/.../exec",
                    "previous_year": 2026, "label": "2027年度"}}}
```

翌年度は `years` に1項目足して `default_year` を変えるだけ。exe の作り直しは要らない。

## シート定義（Hub が検証する正本。Apps Script v2 はこれに合わせる）

共通: 1行目がヘッダーで、**列名は先頭からこの順に完全一致**（末尾に列を足すのは可）。
日時は Apps Script も `yyyy-MM-dd'T'HH:mm:ss` の文字列で書く。**コード列は「書式なしテキスト」**にする
（前ゼロの `0301619` や英字入りの `13X5035440` を数値にさせない）。

### 設定（キー / 値 / 備考）

| キー | 例 | 使う側 |
|---|---|---|
| スキーマ版 | `2027.1` | Hub・Apps Script（不一致なら止まる） |
| 年度 | `2027` | 両方（年度設定JSONと一致必須） |
| 前年度 | `2026` | Hub（jinjer 履歴のどの年度を前年度とみなすか） |
| 受付開始 / 受付終了 | `2027-02-01` / `2027-02-28` | Apps Script の受付期間ガード。Hub は表示 |
| 受診期間開始 / 受診期間終了 | `2027-04-01` / `2028-03-31` | Apps Script（その他健診予定日の検証） |
| 回答受付 | `1` / `0` | Apps Script の緊急停止 |
| WebアプリURL | `https://script.google.com/.../exec` | Apps Script が案内メールに使う |
| 案内メール件名 / 案内メール本文 | `{氏名}` `{URL}` `{受付終了}` 置換 | Apps Script |
| 担当者連絡先 | メール | Apps Script（画面表示） |

### 選択肢（区分 / コード / 表示名 / 有効 / 並び順 / 別名 / 備考）

- 区分は `機関`／`種別`／`追加検査`／`続柄`。
- `有効` は空欄か `1` で有効、`0` で無効（プルダウンから消えるが、過去の回答は表示できる）。
- `並び順` は数値。空欄は末尾。
- `別名` は `;` 区切り。**jinjer 側のテキスト表記（前年度の健診機関名・健診内容の選択肢名）をここに書くと、
  対象者登録のときにコードへ寄る**。

hpm.txt（HPM の機関一覧・種別一覧）を貼るときの手順:

1. `健診機関` 見出しの下の50行を「コード / 表示名」として貼り、左に `機関` 列を足す。
2. `健診種別` の6行を同様に `種別` として貼る。
3. 固定行を足す: `機関 | OTHER | その他 | 1 | 999`、`追加検査 | GYN | 婦人科検診 | 1 | 1 | 婦人病検査;婦人科健診`、
   `続柄 | 妻 | 妻`、`続柄 | 夫 | 夫`。
4. jinjer 表記の別名を入れる（既定の対応）: `10` ← `基本健診`、`12` ← `1日人間ドック・バリウム`、
   `13` ← `1日人間ドック・胃カメラ`、`15` ← `1日人間ドック`。`11`・`14` は jinjer に対応なし。
5. **判断が要る行**（貼るときに決める）:
   - 同名2件: 「東京品川病院 総合健診センター」= `130192` と `1310970590`／「さがみはら」= `1412600385`
     （相和会 健診ステーション）と `1412612109`（検診ステーション）。両方残すか片方を `有効=0` にするか。
   - `13X5035440` は hpm.txt では「関東ITソフトウェア健康組合(大久保健診センター)」。既存の
     `健康診断HPM変換マスタ.xlsx` では桜十字グランフロント大阪に付いている。hpm.txt を HPM 原本とみなし、
     **HPM変換マスタ側の是正は別件**。
   - `14 雇用時の健康診断` は年次申込には出番が無いが、要望どおり載せる。

### 対象者（1年度1人1行。1〜14列は Hub、15列以降は Apps Script が書く）

`年度 / 社員番号 / 氏名 / 社用メール / 在籍区分(0在籍 1退職 2休職) / 前年度情報元(履歴・現在値・なし) /
前年度健診機関コード / 前年度健診機関名 / 前年度健診種別コード / 前年度健診種別名 / 前年度追加検査(;区切り) /
前年度健診機関(原文) / 登録日時 / 登録者 ｜ トークンハッシュ(SHA-256 hex) / 送信日時 / 送信回数 /
初回アクセス日時 / 申込状態(未送信・送信済・回答済・再回答待ち・無効) / 受付番号 / 回答版 / 回答日時 / 備考`

**Hub はトークンを生成も保持もしない。** Apps Script の送信メニューが送信時に生成し、ハッシュだけを書く。

### 回答（追記専用・上書きしない）

`回答日時 / 受付番号(HC-{年度}-{社員番号}-{回答版2桁}) / 年度 / 社員番号 / 回答版 / 氏名 / 社用メール /
申込区分(same・change) / 健診機関コード / 健診機関名 / その他医療機関名 / 健診種別コード / 健診種別名 /
追加検査 / その他健診予定日 / 被扶養者申込(1・0) / 続柄 / 被扶養者氏名 / 備考 / トークンハッシュ / 回答元`

### 監査ログ

`日時 / イベント / 実行元(Hub・AppsScript) / 実行者 / 年度 / 社員番号 / 詳細`。
Hub は `REGISTER_BATCH`・`REGISTER`。Apps Script は `SETUP SEND RESEND FIRST_ACCESS SUBMIT REOPEN`。

## 回答読込の判定（`responses.py`）

- 先にシート構成（5シート・列名・スキーマ版・年度）を検証し、通ってから対象者・回答の行を読む。
- 状態: 未送信 → 送信済み・未アクセス → URLが開かれた記録あり → 回答済み／再回答待ち／無効／取込不可。
  「初回アクセス」はメールのセキュリティ検査でも付くので、本人が見た証拠にはしない。
- 取込不可（error）: (年度, 社員番号, 回答版) 重複／受付番号重複／対象外社員／年度違い／選択肢不明／
  対象者と回答の状態不一致（受付番号・回答版のずれ、回答済なのに回答なし、未送信なのに回答あり）／
  「前年度と同じ」なのに前年度情報なし。警告: 無効化された選択肢、「その他」なのに医療機関名空、
  被扶養者希望なのに続柄・氏名空、在籍区分が退職・休職。
- 最新回答は **回答版の最大**で決める（回答日時では決めない）。

## 対象者登録の規則（`targets.py` / `jinjer_source.py`）

1. 貼り付けテキストを NFKC → 改行・カンマ・空白で分割し、20始まり7桁だけ通す（重複は1件に束ねて警告）。
2. jinjer の社員一覧（退職者含む）から氏名・社用メール・在籍区分。**登録不可**: jinjer に無い／メール空／
   `@nmht.co.jp` 以外（緩めるなら `targets.py` の `EMAIL_DOMAIN`）。**警告のみ**: 退職・休職。
3. 前年度: 「健康診断履歴」(menu 15) の `年度 == 前年度` → 「健康診断」(menu 14) の現在値 → なし。
   健診機関のテキストと健診内容の選択肢名は、選択肢シートの表示名・別名で HPM コードへ寄せる。
   寄せられない（機関が不明、種別が0件か2件以上）ときは「なし」にして原文を `前年度健診機関(原文)` に残す
   → 本人は「前年度と同じ」を選べない。
4. 既存「対象者」（同じ年度）と突合: 無ければ **追加**、主要列（氏名・メール・前年度情報元・機関コード・
   種別コード・追加検査）が同値なら **変更なし**、違うか回答済み（申込状態・受付番号・回答シート）なら **競合**。
   **競合か登録不可が1件でもあれば登録できない**。同じ貼り付けの再実行は全件「変更なし」（冪等）。
5. プレビューは管理者PCのローカル `HEALTH_APPLY_SESSION_DIR` に JSON で置き（`happly_` + uuid）、2時間で無効。
   登録は「本人のプレビュー」「確認語 `REGISTER {年度} {追加人数}`」を要求し、**シートを読み直して差分を
   再計算し、追加行の指紋（sha256）が一致するときだけ**追記する（違えば 409 で何も書かない）。
6. 追記は 対象者（先頭14列） → 監査ログ（`REGISTER_BATCH` 1行＋`REGISTER` 1人1行）の順。監査ログだけ失敗しても
   再実行で「変更なし」になる。追記後に対象者を読み直して全員いることを確かめる。

## 準備（谷津さん側。Hub の実接続テストの前）

1. Google Cloud で Sheets API を有効化し、健診専用サービスアカウントを作って鍵JSONを
   `%LOCALAPPDATA%\KintaiChecker\health_apply\service_account.json` に置く（共有フォルダ・リポジトリ・
   `.env` には置かない。`.env` は exe に同梱される）。
2. 2027年度スプレッドシートを作り、5シートと1行目ヘッダーを上の定義どおりに用意。
   「選択肢」に hpm.txt を貼る（上の手順）。コード列は書式なしテキスト。
3. サービスアカウントの `client_email`（Hub の状態画面に出る）へ **編集者** として共有。
4. `健診申込_年度設定.json` と `健診申込_閲覧許可ユーザー.csv`（列: ユーザー名, 表示名, 備考）を
   `Z:\API連携\docs\` に置く。
5. 「回答」に架空の社員番号でサンプル1〜2行を入れ、Hub の「回答を読み込む」で表示を確認。
