# 社労士モード（前田事務所へ渡す給与CSV）

jinjer の給与明細から、社労士（前田事務所さん）へ毎月渡している 60 列の CSV を作るモード。
**jinjer へは読みに行くだけで、一切書き込まない。**

- 実装: `services/sharoushi_export.py`（純ロジック）／`app.py` の `/sharoushi_run`・`/sharoushi_download`
- 画面: モードタブ「社労士CSV」
- テスト: `tests/test_sharoushi_export.py`
- マスタ作成: `python tools/build_sharoushi_masters.py`
- 出力: `outputs/sharoushi/{YYYYMM}/前田事務所{作成日}.csv` と `備考{作成日}.csv`（cp932・CRLF・非コミット）

## なぜ作ったか

2026-07 支給分までは手作業で作って社労士へ渡していた。見本ファイル
（`前田事務所20260813.csv` ＝ 2026-07 支給分）を jinjer の実データと突き合わせたところ、
**60 列すべてが給与明細 API だけから機械的に再現できる**ことが分かったので自動化した。

初回の本番運用は **2026-08 支給分**。

## 入力

給与明細 API（`/v1/employees/salary-statements`）**1本だけ**。
`statements[].basic_info` に氏名（last_name / first_name）と給与体系（`salary_system.name`）が
入っているので、従業員マスタの別取得は要らない。
キャッシュは経理モードと共用する（`outputs/keiri/raw/salary_statements_{ym}.json`）。

外部マスタ（どちらも共有フォルダ。直せば exe の再ビルドなしで次回実行から効く）:

| ファイル | 既定パス | 役割 |
|---|---|---|
| 列マッピング | `Z:\API連携\docs\社労士モード_列マッピング.csv` | どの列にどの jinjer 項目を入れるか |
| 追加支給台帳 | `Z:\API連携\docs\社労士モード_追加支給台帳.csv` | 給与計算後に発生した支給を足す |
| 備考台帳 | `Z:\API連携\docs\社労士モード_備考台帳.csv` | イレギュラー5項目の発生理由 |

列マッピングが無いときはコード内の既定表（`DEFAULT_COLUMN_MAPPING`）で動く。

## 列の対応

**給与体系ごとに中身が変わる**（月給制1／月給制2／月給制3／時給制1／管理監督者）。
列マッピングCSVの `給与体系` が空なら全体系共通、埋まっていればその体系だけ。
同じ（列番号, 給与体系）の行が複数あるときは**合計**する。

計算で埋める列（マッピングでは指定できない）:

| 列 | 式 |
|---|---|
| 41 総支給額 | `雇用保険対象額(other5) ＋ その他(allowance52)` |
| 52 社会保険料計 | 雇用保険＋健保＋介護＋厚年＋子ども子育て支援金＋**社保調整(deduction4)** |
| 53 控除合計 | 社会保険料計＋所得税＋住民税＋年調過不足＋欠勤控除＋**社宅家賃＋貸付金返済** |
| 54 差引支給額 | `差引支給額(payment1)` そのまま |
| 55 口座1振込額 | `口座1振込額(payment2) − 立替金(a51) − 立替金（顧客請求分）(a50)` |
| 42 課税対象額 | 常に空（見本ファイルがそうなっている） |

### 立替金の扱い（いちばん間違えやすいところ）

**総支給額と口座1振込額からは引き、差引支給額からは引かない。**
総支給額が雇用保険対象額ベースなのは、jinjer の雇用保険対象額が元々 立替金・その他を
含まないため。結果として「立替金を引いた総支給額」になる。

社宅家賃・貸付金返済・社保調整には専用列が無く、合計欄の中にだけ乗る。

## 決定事項（2026-08-14 谷津さん）

1. **時給制の超過・深夜・休日の金額は明細列を空のまま**にする。差額調整(allowance24)に
   含まれているため。17 超過時間分〜22 超過精算分は常に空。総支給額には含まれている
2. **時給制の勤怠時間列は見本どおり**（06 深夜残業時間←前月総労働時間、07 休日出勤時間←
   前月深夜労働時間、08 休日深夜時間←前月総労働時間）。列名と中身がずれているが直さない
3. **社員番号 20YY 始まりだけ出す**。7777777（今井）・9999999（得笑・給与体系「テスト」）とも除外
4. **allowance15／allowance12 は全員一律で「調整手当」列**。「職能手当」列は常に空
   （見本では 2017012 だけ職能手当に入っていたが是正した）
5. **給与計算後の追加支給は台帳CSVで足す**。差引支給額と立替金列に加算し、
   口座1振込額と総支給額は据え置く（jinjer に立替金として入っていたのと同じ形になる）

## 月をまたぐと変わるもの（要注意）

| 項目 | 〜2026-07 支給分 | 2026-08 支給分〜 | 対処 |
|---|---|---|---|
| 調整手当 | `allowance15` | `allowance12` | マッピングに**両方**入れて合計（片方は必ずゼロ） |
| 時給制の allowance2 | 前月超過勤務（出さない） | みなし給（16列目へ） | **体系別名で判定**。月で切らない |
| その他手当 | `allowance21` | `allowance20` | **両方**を34列目に入れて合計（着地先は jinjer のテンプレート設定次第） |

`allowance2` を ID だけで判定すると月給制と時給制で意味が違うため事故になる。
体系別名が「当月みなし時間外手当／当月みなし深夜手当／みなし手当／みなし給」のときだけ
16 列目に入れる。それ以外で「前月〜」でもない名前になったら未知項目として止める。

## 備考CSV（イレギュラー発生分の理由）

本体CSVと一緒に `備考{作成日}.csv` を出す。社労士は金額だけ見ても理由が分からないため。
列: 社員番号／氏名／給与体系／項目／金額／理由

対象は経費チェックモードの「イレギュラー経費」から手入力する5項目
（`services/keihi_payroll_import.py` の `MANUAL_ITEM_KEYS` と同じ）:

| 項目 | jinjer |
|---|---|
| 定常外業務対応手当 | allowance19 |
| その他手当 | allowance20 ＋ allowance21 |
| 現物支給 | allowance53 |
| 支給過不足調整 | allowance54 |
| 社保調整 | deduction4（控除項目） |

**金額は jinjer が正、理由だけを台帳に持たせる**（二重管理にしない）。その月に金額が
発生した人だけが行になる。理由は画面の「イレギュラー発生分の理由」から入れて保存すると
台帳へ書かれ、そのまま作り直しが走る。理由を空にすると台帳から消える。

理由が未入力の行は画面に件数が出る。未入力でも備考CSVは出る（理由欄が空になるだけ）ので、
渡す前に埋めるかどうかは人が決められる。

2026-08 実績は10件（定常外業務対応手当2・その他手当2・現物支給2・支給過不足調整2・社保調整2）。

## 未知項目の検知（jinjer 側の項目移設に気づくため）

支給項目・控除項目に金額があるのに、出力にも計算にも乗っていないものがあったら
**既定ではエラーで止める**。画面には社員番号・項目ID・項目名・金額が並ぶので、
列マッピングCSVに追記してから実行し直す。内容を確認したうえで
「このまま出力する」を押せば続行もできる。

差額調整の再掲（allowance3〜6）と前月基礎時給（allowance7）は、意図して出さない項目として
`IGNORED_KEYS` に理由つきで登録してあるので検知に引っかからない。

## 検知網が本番で効いた実例（2026-08 初回実行）

未知項目が4件出た。いずれも **その月から使われ始めた項目**で、見本ファイル（2026-07）が
全ゼロだったため列の対応が分からなかったもの:

- `allowance19 定常外業務対応手当` 2名 75,000円 → 32列目へ
- `allowance20 その他手当` 2名 104,220円 → 34列目へ

「その他手当」は jinjer に allowance20 と 21 の2つあり、経費の追加投入がどちらに着地するかは
jinjer 側のテンプレート設定が決める。実測で 2026-07 は 21、2026-08 は 20 だったので、
**両方を34列目に入れて合計**する形にした（同じ月に両方が入ることはない）。

## 検証

2026-07 支給分のキャッシュで、見本ファイル **231 行 × 60 列が一致**する
（`tests/test_sharoushi_export.py` の `RegressionTests`）。
差分は上の決定事項 3・4 によるものだけ:

- 2017012 の職能手当 10,000 → 調整手当へ移動
- 7777777・9999999 の 2 行を出力しない

**2026-08（本番初回）も 231 行・未知項目0件**で生成できた。
調整手当は allowance12 に104名2,713,290円（移設対応が効いている）、
時給制52名の allowance2 は体系別名が「みなし給」に変わっていることも確認した。

## 運用

1. 画面で「社労士CSV」タブ → 支給月を入れて実行
2. 要確認（未知項目・想定外の給与体系・複数明細・理由未入力）が出ていないか見る
3. 「イレギュラー発生分の理由」を埋めて保存（保存すると自動で作り直される）
4. プレビューで先頭 10 人ぶんを確認
5. 本体CSVと備考CSVをダウンロードして社労士へ渡す

給与計算後に追加で支払った分があるときは、先に追加支給台帳へ 1 行足してから実行する。
